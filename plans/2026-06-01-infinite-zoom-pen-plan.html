Infinite Zoom Pen Implementation Plan

The goal is to make Zenno feel like an actual thinking canvas: crisp ink at deep zoom, a default pen that naturally creates tiny detailed writing when zoomed in, an explicit Screen/Canvas pen-size toggle, and zoom that stops feeling artificially capped.

Product Decisions

Default Pen Mode

Screen

New strokes should feel the same under the hand at every zoom. At 400%, a normal-feeling word becomes a tiny detailed word when zoomed back out.

Secondary Pen Mode

Canvas

Use this when the mark is structural: headings, arrows, boxes, dividers, visible scaffolding, and anything that should keep its canvas importance.

Zoom Feel

Continuous

No forced snap while pinching or scrolling. Keep quick preset buttons, but do not make the camera land on stops unless the user asks.

Old Strokes

Preserve

Existing strokes stay real vector strokes. The renderer gets sharper; the stored note data is not rewritten unless a future migration is explicitly needed.

The rule: screen mode is for diving deeper into thought. Canvas mode is for building visible structure.

Codebase Evidence

Area What Exists Today Why It Matters
Stroke model lib/canvas/model/stroke.dart stores centerline points in world coordinates, pressure, color, width, and tool kind. Ink is already vector source data. The problem is not "bitmap ink" in the core model.
Stroke renderer InkElement.outlinePath lazily builds one perfect_freehand outline path and caches it for the element lifetime. At high zoom, a cached low-detail world-space outline can expose polygon edges and old sample spacing.
Live renderer LiveStrokePainter builds an outline for the active stroke using the same builder. Live and committed ink should share the same quality logic so the stroke does not change appearance when committed.
Zoom clamp CanvasTransform.minScale = 0.005 and maxScale = 256.0. This is wide but still a wall. Infinite zoom needs much deeper practical bounds and precision hardening.
Point persistence InkCodec writes x/y as float32. Float32 is risky for tiny strokes made at deep zoom, especially away from the origin. New tiny writing needs float64 coordinates.
Pen settings CanvasController.penWidth is saved as canvases.activePenWidth. There is no width mode. We can add mode as a canvas tool setting without changing existing stroke rows.
Hover preview CanvasOverlayPainter draws a screen-space hover ring, but CanvasView passes penWidth directly. The preview needs to show the resolved screen diameter for Screen vs Canvas modes.

enum PenWidthMode { screen, canvas }

double resolveStrokeWidthWorld({
  required double selectedWidth,
  required double viewportScale,
  required PenWidthMode mode,
}) {
  return switch (mode) {
    PenWidthMode.screen => selectedWidth / viewportScale,
    PenWidthMode.canvas => selectedWidth,
  };
}

Key Technical Shift

The stored stroke remains simple: centerline points plus final world-space width. The renderer becomes smarter by rebuilding or caching paths at the quality needed for the current zoom. This avoids changing old note meaning while fixing the ugly high-zoom view.

Implementation Phases

Phase 0

Baseline Reproduction

Add a small debug/repro test canvas or test helper that creates strokes at 100%, 400%, and a very deep zoom. Capture the current failure visually before changing behavior.

  • Record existing max zoom behavior.
  • Create one old-style stroke with sparse points and inspect it at high zoom.
  • Create one new live stroke at high zoom and compare live vs committed appearance.
Phase 1

Precision Foundation

Upgrade new ink persistence from float32 x/y to float64 x/y so tiny high-zoom writing survives save/load.

  • Add InkCodec format v3. Keep v1 and v2 decode forever.
  • Write new strokes as v3 with float64 coordinates.
  • Update repository and codec tests from float32 tolerance to near-double tolerance for new blobs.
  • No SQL table migration is required for the point blob itself.

// azimuth: float32

Phase 2

Screen / Canvas Pen Modes

Add explicit pen-width semantics, defaulting to Screen.

  • Add PenWidthMode to the input/tool settings layer.
  • Add CanvasController.penWidthMode, setPenWidthMode, and a resolver for final world width.
  • Persist the mode on the canvas row with a schema v9 column such as activePenWidthMode.
  • Load/save the mode through CanvasToolSettings.
  • Update CanvasToolbar with a small segmented control: Screen and Canvas.
  • Update hover preview so Screen mode stays visually constant and Canvas mode grows/shrinks honestly with zoom.
ALTER TABLE canvases
ADD COLUMN active_pen_width_mode INTEGER NOT NULL DEFAULT 0;

-- 0 = screen, 1 = canvas
Phase 3

Zoom-Aware Ink Rendering

Replace the one-size-fits-all cached outline path with a renderer-owned path cache that can choose normal, high-zoom, and overview strategies.

  • Keep the current cached outline for normal zoom while the new path cache is introduced.
  • For high zoom, build outlines from resampled centerlines so old sparse strokes do not reveal harsh angles.
  • Use the same path builder from ElementsPainter and LiveStrokePainter.
  • Bypass tile pictures for high-zoom ink if they prevent quality-aware rebuilding.
  • Keep overview LOD for very low zoom so giant maps stay fast.
enum StrokeRenderQuality { overview, normal, highZoom }

class StrokePathCacheKey {
  const StrokePathCacheKey({
    required this.strokeId,
    required this.revision,
    required this.scaleBucket,
    required this.quality,
    required this.isComplete,
  });

  final String strokeId;
  final int revision;
  final int scaleBucket;
  final StrokeRenderQuality quality;
  final bool isComplete;
}
Phase 4

Effectively Infinite Zoom

Raise zoom bounds after precision and rendering are safe. This gives the Ahmni-like feeling without pretending the math is literally endless.

  • First target: symmetric powers of two such as 1 / 65536 to 65536.
  • Expand snap-stop lists only for toolbar labels/presets. Do not snap live gestures.
  • Add scale formatting that remains readable at extreme zoom.
  • Audit hit testing, eraser radius, lasso, grid, PDF/image raster scheduling, and export bounds at extreme scale.
abstract final class CanvasTransform {
  static const double minScale = 1 / 65536;
  static const double maxScale = 65536;

  static double clampScale(double scale) {
    return scale.clamp(minScale, maxScale);
  }
}
Phase 5

Deep-Zoom Hardening

If Phase 4 feels good but still has edge-case precision trouble, use the existing worldOriginX/worldOriginY columns as the start of a rebasing system.

  • Keep active coordinates close to the current thinking area.
  • Persist a world origin offset separately from local element coordinates.
  • Rebase only at safe moments, never mid-stroke.
  • Gate this behind tests because note data integrity is the highest-risk part of the plan.

Validation Plan

Unit Tests

Pen width resolver, zoom clamp boundaries, v3 ink codec round trips, v1/v2 legacy decode, and toolbar state persistence.

Widget Tests

Toolbar toggles Screen/Canvas, width buttons still work, hover preview receives correct screen radius, and saved canvases reload the selected mode.

Render Tests

Deterministic strokes render nonblank at 100%, 400%, and deep zoom; live and committed stroke paths stay visually consistent.

Manual QA

Use an S Pen or mouse to draw at 100%, 400%, 1600%, and deeper. Zoom back out and confirm Screen strokes become tiny details while Canvas strokes keep note structure.

test('screen mode resolves selected width through current zoom', () {
  expect(
    resolveStrokeWidthWorld(
      selectedWidth: 4,
      viewportScale: 4,
      mode: PenWidthMode.screen,
    ),
    1,
  );
});

test('canvas mode keeps selected width in world units', () {
  expect(
    resolveStrokeWidthWorld(
      selectedWidth: 4,
      viewportScale: 4,
      mode: PenWidthMode.canvas,
    ),
    4,
  );
});

Manual Test Script

  1. Open a canvas with the default Screen mode.
  2. At 100%, write a normal word with width 4.
  3. Zoom to 400%, write another word with width 4.
  4. Zoom back to 100%. The second word should be smaller and still crisp.
  5. Switch to Canvas mode at 400% and write a third word. Zoom back out. It should match the 100% word's canvas size.
  6. Zoom deeply into an old stroke. Edges should be smooth enough to inspect without the "magnified bitmap" feeling.
  7. Save, close, reopen. Tiny Screen-mode strokes should keep their positions and shape.

Risks And Guardrails

Risk Why It Matters Guardrail
Tiny strokes collapse after save/load Float32 coordinate precision is not enough for deep zoom detail in all locations. Ship v3 float64 point blobs before making Screen mode the default.
High-zoom rendering gets slow Rebuilding high-quality outlines for every visible stroke can cost too much. Use scale-bucket caching, viewport culling, and keep overview rendering for low zoom.
Old strokes still look imperfect Old strokes may have sparse samples because the original hand motion was captured at lower detail. Use resampling/interpolation to make them visually smooth, while accepting that missing original hand data cannot be recovered perfectly.
Mode labels are confusing Bad naming would interrupt flow every time Karl switches pen behavior. Use simple labels: Screen and Canvas. Tooltips explain one sentence each.
Zoom math breaks selection, eraser, or imports Many tools convert between screen and world units. Audit every radius/threshold conversion: eraser, lasso, hit testing, nudge, grid, PDF raster bucket, and export.
Data integrity rule: do not rewrite existing stroke blobs just to upgrade them. Decode old blobs, write new blobs in v3, and only migrate existing data if there is a separate, tested reason.

Definition Of Done

Zenno is done with this feature when the default Screen pen lets Karl zoom in, write a tiny detailed note comfortably, zoom back out, and still see crisp vector ink; Canvas mode remains available for structural strokes; saved notes survive reload; and the app no longer feels like it hits an artificial zoom wall during normal thinking.
