The single biggest win

Scope the rebuilds. One ChangeNotifier with 87 notifyListeners() call sites drives the whole editor: every ink frame, every hover event (~120 Hz), and every pan frame rebuilds CanvasView, the entire toolbar, and an 18-closure shortcut map. RepaintBoundary stops paint, not build. Splitting the notifier (items 2.1 / 4.1) is the highest-leverage change in this plan and a prerequisite for the pen feeling right.

1 · Critical correctness & data safety

4 items

Small diffs, real user-data consequences. Do these first, in any order.

P0

File-cleanup race can delete a just-imported image

DONE~½ day

Problem — library_providers.dart:18-25 fires cleanupOrphanedFiles() as a fire-and-forget side effect of the provider factory, and the provider is autoDispose — so it re-runs every time the user re-enters the Library. CanvasImporter copies a picked file into canvas_media/ before the element row exists; a cleanup pass landing in that window deletes the user's file.

Fix — Move cleanup out of the factory into a one-shot startup task in main.dart; mark the repository @Riverpod(keepAlive: true). Have the importer stage files in canvas_media/.staging/ (excluded from cleanup) and move them only after the row commits.

Verify: new test — import file, run cleanup mid-window, file survives; plus a temp-dir test for deleteOrphanedOwnedLibraryFiles (never deletes outside owned roots, rejects symlink escape).
P0

No flush when Android backgrounds the app

DONE~2 h

Problem — only _closeEditor/dispose call flush() (canvas_editor_page.dart:213, 267). Android freely kills backgrounded apps; up to 400 ms of debounced viewport state plus any in-flight element write is lost.

Fix — make _CanvasEditorPageState a WidgetsBindingObserver; call _controller.flush() on AppLifecycleState.paused.

Verify: widget test simulating lifecycle change asserts repository received the pending write.
P0

Tool-settings write storm: one SQLite transaction per drag frame

DONE~2 h

Problem — _saveToolSettings() (canvas_controller.dart:1926) JSON-encodes the whole 8-slot wheel and issues a canvases UPDATE, undebounced, from every setter — and those setters are wired to continuous slider/drag handlers (canvas_toolbar.dart:918, 928, 938, 1580). Width drag = one DB transaction per frame. Same for setPaperStyle.

Fix — mirror the existing 400 ms viewport debounce pattern (canvas_controller.dart:227, 1040); cancel in dispose(), drain in flush().

Verify: test — 50 rapid setPenWidth calls produce exactly one repository write after the debounce window.
P1

Final pen-up point is never appended to the stroke

DONE~2 h

Problem — _onPointerUp (canvas_view.dart:742-747) calls endStroke() without pushing the up-event's position. Combined with EMA smoothing lag, every stroke terminates short of where the pen lifted — visible on short ticks, commas, fast flick tails.

Fix — for _ToolGesture.draw, push one final unsmoothed sample at event.localPosition before endStroke(), bypassing both PenInputProcessor and the min-distance filter (add force: true to appendToStroke, canvas_controller.dart:1283).

Verify: input test — stroke's last point equals pointer-up position.

2 · Pen & ink engine

8 items

The input model is already strong — raw Listener (no gesture-arena latency), structural palm rejection, frame-coalesced live-stroke notifications, a real vector eraser. These items close the gap between "works" and "feels like Samsung Notes."

P0

2.1 · Stop rebuilding the world on every ink frame

DONE~1 day

Problem — canvas_editor_page.dart:488-490 wraps the whole Scaffold body in ListenableBuilder(listenable: _controller); the toolbar adds a second one (canvas_toolbar.dart:324). Every appended point rebuilds the full widget tree 60–120×/sec. Worse: setHoverPoint (canvas_controller.dart:1974) notifies unconditionally at ~120 Hz — merely hovering the S Pen rebuilds the entire editor.

Fix —

  • Narrow the outer ListenableBuilder to the load-state gate only; hoist CanvasView/CanvasToolbar outside it. Hoist the 18-entry CallbackShortcuts map (canvas_editor_page.dart:546-622).
  • Split the notifier: liveStrokeTick, viewportNotifier, toolNotifier, elementsNotifier. Wrap only the live layer in a ValueListenableBuilder; painters can take repaint: directly and skip widget builds entirely.
  • Guard setHoverPoint with an equality check and route it through _notifyLiveStrokeSoon.
Verify: rebuild counter in a widget test — toolbar builds during a 100-point stroke drop from ~100 to 0.
P0

2.2 · Incremental live-stroke tessellation (kill the O(n²))

DONE~1–2 days

Problem — LiveStrokePathCache keys on revision, bumped every point (live_stroke_painter.dart:34-39, canvas_controller.dart:1298) — the cache never hits mid-stroke. Each frame runs getStroke over the whole buffer plus a fresh List.unmodifiable copy (canvas_controller.dart:341). At ~1 px sampling a screen-crossing stroke is ~2,000 points; long strokes degrade visibly as they grow.

Fix — frozen-prefix + live-tail: every K≈32 points, record points [0..n−K] into a ui.Picture (with ~8-point overlap for smoothing continuity); per frame, tessellate only the tail and drawPicture + drawPath. Stop copying the point list per frame — expose an unsafe view or memoize the snapshot against the revision.

Verify: golden test on buildStrokeOutline first (none exists); then frame-time trace on device with a 3,000-point stroke.
P0

2.3 · Rewrite the stabilizer — it's backwards, and you're smoothing twice

DONE~1 day + on-device tuning

Problem — pen_input_processor.dart:74-82: damping grows with speed, so fast strokes get more lag and slow (jittery) strokes get less filtering — the inverse of every shipped stylus stabilizer. It's also per-sample rather than per-dt, so lag varies with the S Pen's report rate (~120–240 Hz). And perfect_freehand's streamline: 0.4 (stroke_builder.dart:58) adds a second low-pass on top.

Fix — time-constant EMA: alpha = 1 − exp(−dt/τ) with τ shrinking as speed rises. Then set streamline: 0.0 everywhere — own the filtering in exactly one place.

final dt = ((tMicros - prevMicros) / 1e6).clamp(1e-4, 0.05);
final speed = distance / dt;
final tau = profile.stabilizer * (1.0 / (1.0 + speed / 800.0)); // less smoothing when fast
final alpha = 1 - math.exp(-dt / math.max(tau, 1e-4));
final smoothed = previous + (point - previous) * alpha;
Verify: unit test — identical stroke sampled at 120 Hz vs 240 Hz produces near-identical output; hand-feel pass on the Tab S9 FE.
P1

2.4 · Tail prediction on the live layer

DONE~1 day

Problem — no extrapolation ahead of the last sample; perceived pen-to-ink gap ≈ 25–35 ms. isComplete: false even draws the tail slightly behind the last point.

Fix — extrapolate ~1 frame from the last 3 samples' velocity, clamped to 8–12 px and disabled at high curvature; append to the painter's tail path only, never to the stroke data. (Android 14's MotionPredictor via platform channel is the stretch goal; the Dart version gets most of the benefit.)

P1

2.5 · Close the palm-rejection gap around pen-down/pen-up

DONE~½ day

Problem — touch is only suppressed while a tool pointer is down (canvas_view.dart:311, 551). Before the nib lands and right after it lifts, a resting palm pans the viewport — the classic mid-sentence canvas jump.

Fix — track _lastStylusEventMicros (hover events already arrive, canvas_view.dart:1295); reject touch-down within ~400 ms of any stylus activity or while the stylus hovers. Consider event.radiusMajor as a secondary palm heuristic.

P1

2.6 · Per-tool perfect_freehand tuning + built-in tapers

DONE~1 day

Problem — one hardcoded parameter set for all six tools (stroke_builder.dart:56-60): highlighter/marker get pressure thinning they shouldn't; non-pressure input gets dead uniform width instead of free simulatePressure; applyTaper (pen_input_processor.dart:108-129) hand-rolls a 4-point width step, applied only at commit — so live and committed stroke ends look different.

Fix — a StrokeOptions factory keyed on tool kind (pen: thinning 0.55 + StrokeEndOptions tapers; highlighter: thinning 0, cap off; etc.), simulatePressure: !pressureEnabled, easing: profile.pressureCurveFn. Delete the hand-rolled taper and the commit-time taper (canvas_controller.dart:1317-1321).

P1

2.7 · Incremental, previewable eraser

DONE~1–2 days

Problem — appendErase (canvas_controller.dart:2031-2038) appends every move event unfiltered and notifies unbatched (~2,400 full-page rebuilds per 10 s scrub); all hit testing defers to pointer-up where polylinesWithinDistance (canvas_geometry.dart:69-108) explodes to tens of millions of ops on the UI thread; nothing shows what will be erased until you lift.

Fix — distance-filter and frame-batch the path like ink; hit-test incrementally per new segment against spatialIndex.query() candidates into a _pendingEraseIds set; render pending elements at ~30% opacity; memoize the eraserPath view (mirror _selectedIdsView at canvas_controller.dart:554).

P2

2.8 · Quadratic outlines + ink codec v4

PARTLY DONE~1–2 days

Problem — outline path is a raw polygon (stroke_builder.dart:105-109); facets at high zoom are patched by an expensive Catmull-Rom resampler (:159-197, up to 4,096 points). Codec spends 48 B/point (ink_codec.dart:52-69), persisting derivable velocity and absolute float64 timestamps — dense pages run to tens of MB.

Fix — emit midpoint quadratic Béziers (the upstream JS approach); Skia tessellates curves against the device transform, sharp at any zoom — then delete the resampler and the highZoom cache branch. Codec v4: drop velocity, delta-encode timestamps (int64 base + uint32 delta), pack pressure/tilt into small ints → ~16 B/point. Keep v1–v3 decoders as today.

3 · Tool wheel & canvas UX

8 items

The wheel was enlarged but its type and targets weren't. On the Tab S9 FE nearly every control misses the 48dp minimum, labels are 7 px, and the app has zero haptics.

P0

3.1 · Readable labels & visible tool icons

DONE~1 day

Problem — wedge labels are 7 px, property labels 6.5 px, center 9 px (canvas_toolbar.dart:2709, 2899, 2946) — decorative noise at arm's length, undercutting the whole "easier to scan" branch. And wedge icons are painted in the ink color (:2798): default white pen ink on cream surfaceContainerHigh ≈ 1.1:1 contrast — invisible in light theme.

DONE~1 day

4 · Rendering & data-layer performance

5 items

Beyond the notifier split, a handful of algorithmic fixes that show up on large canvases.

P1

4.1 · Cull before iterating in the painter

DONE~1 day

Problem — _paintVisibleElements iterates all elements per frame to preserve z-order (elements_painter.dart:434), and the tile cache is bypassed whenever anything is selected or dragging (:418) — dragging one stroke on a 20k-element canvas is a 20k loop per frame. The fast path also rebuilds two full maps per paint (:493-499).

Fix — paint from visibleIds sorted by a cached paint-order map; cache elementsById/paintOrderById per elementsRevision (invalidation hook already exists at :74).

P1

4.2 · Linear hydration + id→index map

DONE~1 day

Problem — load() is O(n²) twice over: per-element duplicate scan + sorted-insertion scan (canvas_controller.dart:791-807) on data that arrives pre-sorted. A 5,000-stroke canvas ≈ 50M comparisons on open. Four more linear scans (:1196, 4247, 4381, 4396) hit per-frame paths.

Fix — bulk hydrate: addAll + single sort + SpatialIndex.rebuild (exists, unused — spatial_index.dart:117); maintain an id → index map alongside _elements.

P1

4.3 · Batch element writes; stop re-ensuring the default layer

DONE~½ day

Problem — upsertElements awaits 2 inserts per element in a loop (canvas_repository.dart:350-374): a 500-element lasso move = 1,000+ sequential round trips. _ensureDefaultContentLayer issues an INSERT-OR-IGNORE on every load and every save (:84, 349, 654, 985).

Fix — Drift batch() (used exactly once in the codebase today, focus_repository.dart:335 — the pattern exists); memoize the layer check per canvasId.

P2

4.4 · Move heavy codecs off the UI isolate

DEFERRED~1 day

Problem — InkCodec.decodePoints decodes millions of points synchronously during canvas load; ZennoDocumentCodec does full-canvas JSON on the UI isolate (zenno_document.dart:44, 61). Only one compute() exists in the repo.

Fix — compute() for bulk ink decode on load and for .zenno encode/decode. (PDF and image decode are already engine-side — leave them.)

P2

4.5 · Memoize per-build allocations

DONE~½ day

Problem — selectionBounds scans every element on every build even with nothing selected (canvas_controller.dart:583-599); eraserPath/lassoPath rebuild List.unmodifiable per build (:545-551); spatialIndex.query(...).toSet() allocates per paint (elements_painter.dart:391).

Fix — early-return on empty selection; cache against revision tokens (the _selectedIdsView pattern at :554 is the model).

What was deliberately left

  • Ink codec v4 (2.8) — the quadratic-outline half shipped; shrinking the 48-byte point record is a persisted-format change and wants its own migration and round-trip fuzzing, separate from a rendering commit.
  • simulatePressure for non-pressure devices (2.6) — needs a per-stroke flag in the persisted model, or committed strokes would re-render differently after a reload.
  • God-file split (6.1) and view models (6.2) — large mechanical refactors with wide blast radius. They change no behaviour, so they are better done alone, against the now-larger test suite, than mixed into behavioural commits.
  • Empty state (3.7), a11y pass (5.2), token cleanup (5.3), motion (5.4), isolates for codecs (4.4) — additive polish, none of it blocking. The disabled-state alpha (0.3 → 0.38) from 5.2 did ship with the wheel work.
  • Wheel grip handle (part of 3.5) — the handedness default shipped, but moving drag off the wedges onto a dedicated grip would break the existing drag-from-favourite behaviour that the toolbar tests encode. That is a product decision, not a cleanup.
