Making the pen write like an iPad

Three complaints after the last pen change: lasso got slower, a light tap leaves no dot, and handwriting looks wrong. Two of the three share one root cause, and it is not subtle — the stroke taper is measured in absolute units while strokes are not, so every short stroke is tapered into a hairline.

1Diagnosis

Measured, not guessed. Each finding below was reproduced before anything was written.

R1 · The taper is absolute; a stroke's length is not root cause

buildStrokeOutline passes customTaper: taperLengthFactor * size to perfect_freehand at both ends. For the pen that is 2 × size per end. customTaper is an absolute arc length: the radius ramps from zero over that distance. So any stroke shorter than 4 × size is entirely taper — the ramps from both ends overlap and cancel, and the outline collapses.

Probe, pen tool, size: 4 (so taper = 8 units per end):

pressure  length   outline w × h
0.5       0.2      0.000 × 0.020     <- a tap: nothing
0.5       1.0      1.000 × 0.020     <- a period: hairline
0.5       3.0      3.000 × 0.020     <- a comma: hairline
0.5       8.0      8.000 × 3.500     <- finally has width
1.0       20.0    20.000 × 6.200     <- full width

This is both reported ink bugs. The dot is the obvious victim. The less obvious one: normal handwriting at a normal zoom is made of strokes 3–15 units long — the crossbar of a t, the dot of an i, the tick of an r. Every one of them renders as a sliver while the long sweeps render at full width. The inconsistency is what reads as "ugly".

The single-point _dotPath fallback does not save the tap, because a tap is almost never one point: _appendPenUpSample force-appends the pointer-up position, and a real nib always moves a fraction of a unit between down and up. Two points, sub-unit apart, fully tapered — invisible.

R2 · Smoothing was moved from space to time root cause

The previous change set streamline: 0 and moved all filtering into PenInputProcessor as an exponential filter with a time constant. The stated reason — "don't low-pass twice" — was right about double-filtering and wrong about which filter to keep.

streamline is a spatial low-pass on the centreline. It fits a cleaner curve through the samples; its output depends only on the shape you drew. A temporal filter's output depends on how fast you drew and on the device's report rate. Two identical letters written at different speeds come out as different shapes. That is exactly the instability described as bad penmanship, and it is the thing Apple's engine does not do.

Worse, the temporal filter lags, so _appendPenUpSample then jumps the stroke from the trailing filtered position to the raw lift position — a visible hook at the end of every stroke.

R3 · The lasso keeps every raw sample and copies the list on every repaint perf

appendLasso has no minimum-distance filter — unlike the eraser (_eraseSampleMinDistanceWorld) and the pen (_strokeSampleMinDistanceWorld), both of which thin their input. The S Pen reports at up to 240 Hz and Flutter delivers every historical sample as its own move event, so a two-second loop accumulates thousands of vertices.

Each of those vertices then costs three times over:

  • appendLasso fires _notifyOverlay(), repainting the overlay layer.
  • The lassoPath getter allocates a fresh List.unmodifiable wrapper on every build — O(n) per frame.
  • _paintLasso rebuilds the whole screen-space Path from scratch, projecting every point — O(n) per frame.

Total work is quadratic in loop length. That is the slowdown.

R4 · The predicted tip overshoots, then snaps back feel

LiveStrokePathCache._withPredictedTip extends the drawn tail ~0.8 of the last sample's travel. It exists to hide latency, but it only affects the live path — on commit the extrapolated tip disappears and the stroke visibly retracts. Every stroke ends with a small flick-and-shrink.

R5 · Raw pressure noise becomes width noise feel

Pressure goes from the digitiser straight into the stroke point with no filtering, and thinning: 0.55 is a strong coupling. S Pen pressure is noisy at the ±0.03–0.05 level, which becomes a visible ripple along the edge of a slow stroke. The sample filter even has an explicit pressureChanged >= 0.035 branch that admits extra samples on pressure noise alone.

2What "iPad feel" actually is

Naming the target so the fixes are checkable against something.
PropertyWhat it meansWhere Zenno is now
Shape is speed-invariant The same letter written fast and slow produces the same geometry. Filtering is spatial, not temporal. Violated — R2.
Width is consistent A short stroke and a long stroke at the same pressure are the same thickness. Violated — R1.
Every touch marks The lightest tap leaves a round, visible dot. There is no threshold below which the pen does nothing. Violated — R1.
Ends are asymmetric A pen sets down blunt and lifts to a point. The entry taper is short; the exit taper is long. Symmetric 2×size both ends.
Width has a floor Light pressure thins the line, it never erases it. Apple's minimum is a large fraction of nominal. thinning: 0.55 with no floor.
No visible correction Ink never moves after it is laid down. No snap-back, no retraction. Violated — R4.

3The fixes

Eight changes. Each names its file and the property from §2 it restores.

F1 · Clamp the taper to the stroke's own length fixes the dot + the handwriting

Measure the centreline's arc length and cap each end's taper so the two ramps can never meet. A stroke keeps a full-width middle at any length. 

final double arcLength = _arcLength(points);
// Neither ramp may consume more than 40% of the stroke, so a full-width
// middle always survives — the taper shapes the ends, it cannot eat the line.
final double budget = arcLength * 0.4;
final double startTaper = math.min(style.startTaperFactor * size, budget);
final double endTaper   = math.min(style.endTaperFactor   * size, budget);
lib/canvas/engine/stroke_builder.dart

F2 · Split the taper into entry and exit ends are asymmetric

StrokeToolStyle.taperLengthFactor becomes startTaperFactor + endTaperFactor. The pen goes to 0.35 entry / 1.6 exit: a definite start, a lifting finish. Chisel tools stay at zero on both.

lib/canvas/engine/stroke_style.dart

F3 · Any stroke shorter than a nib-width is a dot every touch marks

Below 0.75 × size of total travel there is no line to draw, only a mark. Route it to _dotPath at the stroke's peak pressure, and raise the dot's floor from 0.5 + 0.5p to 0.62 + 0.38p of the radius so a feather-light tap is still clearly a dot rather than a speck.

lib/canvas/engine/stroke_builder.dart

F4 · Put smoothing back in space shape is speed-invariant

Restore streamline, driven by the profile: streamline = smoothing × 0.62 (default 0.35 → 0.217, in the range the library is tuned for). Then shrink the temporal filter until it only removes hand tremor: _maxTauSeconds 0.045 → 0.012, and gate it to slow motion only, so at writing speed the processor is effectively a pass-through and the shape comes entirely from streamline.

This keeps the anti-tremor benefit that motivated the original change while removing the speed-dependence that made it feel wrong. The two filters no longer compound because they now act in different regimes: temporal below the tremor threshold, spatial above it.

lib/canvas/engine/stroke_builder.dart lib/canvas/input/pen_input_processor.dart

F5 · Smooth pressure, not position width is consistent

Add a short exponential filter over mapped pressure inside PenInputProcessor — pressure is a scalar with no geometry, so filtering it costs nothing in shape or latency. Drop thinning 0.55 → 0.42 and add a pressure floor so the thinnest line is 45% of nominal rather than approaching zero.

lib/canvas/input/pen_input_processor.dart lib/canvas/engine/stroke_style.dart

F6 · Delete the predicted tip no visible correction

Remove _withPredictedTip outright. With F4 the input filter no longer lags meaningfully, so the latency it was compensating for is largely gone — and ink that retracts on commit is worse than ink that arrives a frame late.

lib/canvas/render/live_stroke_painter.dart

F7 · Thin the lasso's input, cache its view fixes the slowdown

  • Minimum-distance filter in appendLasso, mirroring the eraser's: about 1.5 screen px, converted to world units at the current zoom.
  • Cache the unmodifiable lassoPath view and invalidate it on mutation — the same _eraserPathView pattern already in the file. Removes the per-frame copy.
  • Cap the retained loop at 4000 vertices as a backstop, so a pathological drag cannot degrade without bound.
lib/canvas/canvas_controller.dart

F8 · Stop admitting samples on pressure noise width is consistent

Raise the pressureChanged threshold from 0.035 to 0.09, above the S Pen's noise floor. Combined with F5 this stops noise from both thickening the buffer and rippling the edge.

lib/canvas/canvas_controller.dart

5Sequence

  1. F1–F3 — the outline geometry. Highest impact, lowest risk, entirely inside two pure functions.
  2. F4–F5 — the input filter. Changes feel; needs on-device confirmation.
  3. F6 — remove prediction. Pure deletion.
  4. F7–F8 — the lasso and the sample gate. Independent of the ink work.
  5. Tests, analyze, arm64-v8a zenno.apk.

Data safety

Nothing here touches persistence, the ink codec, or any schema. Committed strokes store points, not outlines — the outline is rebuilt from those points on every paint. So all eight changes alter only how existing data is drawn. Notes already on disk render with the new geometry the moment the app opens, and no stored byte changes.
