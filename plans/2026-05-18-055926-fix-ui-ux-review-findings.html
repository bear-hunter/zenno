Assumptions

  • Fix the full review scope, but implement in priority order: High first, shared Mediums second, Low polish last.

Plan

  1. Build shared UI/UX primitives first. Add AppRadii, AppIconSizes, a responsive AppDialog wrapper, a retryable AsyncValueWidget, a friendly error presenter/logger, a guarded async-action helper/widget for buttons, and a destructive-action helper for confirm/undo SnackBars. Replace obvious token violations in theme-level code as the primitives land.
  2. Stop unsaved-changes data loss. Add dirty tracking plus PopScope guards to canvas_editor_page.dart, focus_active_page.dart, focus_review_page.dart, goal_card_detail_sheet.dart, reflection_editor_page.dart, and template_editor_page.dart. Route all app-bar, system-back, scrim, and drag-dismiss paths through the same confirm/save-error flow.
  3. Guard every mutating async action. Apply the guarded helper to canvas import/clear/bookmarks/cards, Focus start/finish/review/distractions/rituals, goal save/delete/date/reflection actions, revision flag/mark/delete/save, library create/rename/delete, settings controls, Kanban actions, and attachment add/detach/rename. Disable controls while in flight, show inline spinners where appropriate, catch failures, use friendly SnackBars, and keep mounted checks after awaits.
  4. Fix error and retry surfaces. Replace raw $error UI text with friendly messages and log raw details. Add retry to board/library/settings/template/canvas-list error panels. Fix masked errors in link_target_dialog.dart and Focus Review’s distraction StreamBuilder. Keep persistent save/import failures visible until resolved, not merely dismissed.
  5. Address destructive-action safety. Add confirmation or Undo to canvas clear, lasso/delete-selection affordances, bookmark removal, Kanban column deletion, ritual retire, attachment detach, canvas delete/rename feedback, reflection delete, and empty-text-note deletion. For Kanban column delete, either delay commit until the Undo window expires or capture enough state to restore the column/cards.
  6. Repair core Canvas UX. Show the real canvas title in the app bar; surface image/PDF import failures; make the toolbar horizontally scrollable and 48dp-hit-testable; make the note and link dialogs responsive; fix link-dialog autofocus and error states; route painter colors through AppColors; improve placeholders/hover contrast; handle PDF page render failures distinctly; tune trackpad/unknown pointer behavior and pinch pointer tracking.

Add Setup start loading/error handling; guard Active back/finish/abandon and Review save/back/discard; make the timer ring responsive with FittedBox and useful semantics; fix open-ended/phase-complete ring states; add distraction/ritual error handling; clamp duration controls and disable stepper bounds; clamp long free text in active/history/setup; add semantics to mode cards, ritual rows, and energy pips.

Bring goal detail sheet to the same save/dirty/error standard as the reflection/template editors; make target date and status note follow one persistence model; fix reflection form setState so Save tracks input immediately; add inline validation/autofocus; add “Duplicate & edit” for read-only templates; reconcile template delete copy with RESTRICT behavior; clamp overflowing goal/reflection/template text.

Risks And Guardrails

  • This is a broad UI pass; keep implementation staged by shared primitives, then High findings, then Medium/Low polish to avoid mixing unrelated behavior changes.
  • Undo for destructive database cascades can be risky. Prefer delayed commit or explicit restore APIs with tests; do not introduce data-loss-prone “undo” shortcuts.
  • Kanban autoscroll and handle-based drag can regress existing drag tests; implement behind small helper classes and test controller math separately from full gesture integration.
  • Settings writes are stream-driven; loading guards must not make controls feel stuck if the stream re-emits slowly.
  • Do not add dependencies, run migrations, or change schema without explicit review if a UI fix can be done safely in presentation/repository layers.
  • No Git commits, pushes, or PRs without Karl’s explicit request.
