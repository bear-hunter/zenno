Zenno canvas evolution plan

Make the canvas feel like a thinking surface.

This plan covers the full workshop thread: better arrow design, customizable stylus-button gestures, PNG/JPG export, infinite zoom behavior, a smarter pen engine, and the extra features worth considering. Shape recognition is intentionally excluded.

Executive Summary

1. Replace arrow rendering with a real arrow system

The current arrow is a single filled triangle computed in ElementsPainter._paintArrow. It should become a styleable shape with open, filled, sketch, curved, elbow, double-headed, dot, diamond, bar, and no-head variants.

2. Add export as a first-class canvas service

Export should support canvas, viewport, or lasso selection; PNG or JPG; transparent or paper background; quality presets; scale controls; padding; and a safe maximum pixel budget.

3. Make input customizable before making it clever

Stylus button behavior should be user-mapped, then the pen should get adaptive smoothing, pressure curves, stabilizer levels, better tapering, hover preview, and optional manual straight-line/snap modes.

Recommended build order

Start with the visible and well-contained improvements: arrow system, quick zoom/framing commands, then export. After that, implement stylus-button mapping and smarter pen controls. Save deep infinite zoom work for last because it touches rendering scale, storage precision, raster quality, selection, export, and performance.

Current Codebase State

The existing canvas architecture is already unusually close to what these features need. The plan should extend it, not tear it down.

What is already strong

  • World-space geometry is already the model layer convention.
  • CanvasTransform.zoomAround already anchors zoom to a focus point.
  • CanvasView cleanly routes stylus/mouse to tools and touch to pan/pinch.
  • SpatialIndex and ElementsTileCache already support large canvases.
  • Lasso selection exposes selectedElements and selectionBounds, which export can reuse.
  • Per-canvas pen color, width, pressure, paper style, and viewport persistence already exist.

What needs changing

  • Arrow style is not persisted. CanvasShapes only stores shapeKind, endpoints, color, and stroke width.
  • The committed arrow painter is hard-coded and visually heavy.
  • Stylus input does not read or map stylus-button state yet.
  • There is no export service or offscreen canvas renderer.
  • Zoom is "wide range" rather than practically infinite: minScale = 0.02, maxScale = 64.
  • The unused worldOriginX/Y columns suggest rebasing was anticipated but not implemented.

Feature 1: Better Arrows

Goal: arrows should look like they belong to the note, not like a fixed triangle pasted onto a line.

Current cause

ShapeKind.arrow is rendered by _paintArrow, which draws a line plus a filled triangular head. Head size is length * 0.22 clamped to 12..56. This makes short arrows look bulky and long arrows feel disconnected from stroke width.

The shape model only persists endpoints and shapeKind, so the user cannot choose arrow semantics or style.

Target behavior

  • Default arrow style should be open, because it is quiet and note-friendly.
  • Arrowhead size scales primarily from stroke width, not overall arrow length.
  • Arrowhead direction follows the final path tangent, including curves and elbows.
  • Live preview and committed rendering use the same renderer.
  • Existing arrows remain readable and editable.

Implementation Plan

Step Change Notes
1 Add arrow style enums and a shape style value object. Keep legacy fields as the source of truth until migration is complete.
2 Move arrow geometry into lib/canvas/tools/arrow_geometry.dart. Pure functions: body path, tangent calculation, head path generation, bounds inflation.
3 Update ShapeElement to carry style and optional control points. Curved arrows need at least one control point. Elbow arrows need a bend mode or bend point.
4 Migrate CanvasShapes to schema v7. Add defaults so older rows round-trip. Use generated migration snapshots after codegen.
5 Update toolbar shape controls. Keep first-level UI compact: shape tool row plus a small arrow-style menu when arrow is selected.
6 Add tests. Geometry tests for heads and bounds, painter golden-ish path tests where practical, repository round-trip tests. 
Path buildArrowBody(ArrowBodyKind body, Offset start, Offset end, List<Offset> controls) {
  switch (body) {
    case ArrowBodyKind.straight:
      return Path()
        ..moveTo(start.dx, start.dy)
        ..lineTo(end.dx, end.dy);
    case ArrowBodyKind.curved:
      final control = controls.isEmpty ? Offset.lerp(start, end, 0.5)! : controls.first;
      return Path()
        ..moveTo(start.dx, start.dy)
        ..quadraticBezierTo(control.dx, control.dy, end.dx, end.dy);
    case ArrowBodyKind.elbow:
      final bend = controls.isEmpty ? Offset(end.dx, start.dy) : controls.first;
      return Path()
        ..moveTo(start.dx, start.dy)
        ..lineTo(bend.dx, bend.dy)
        ..lineTo(end.dx, end.dy);
    case ArrowBodyKind.sketch:
      return buildSketchyPath(start, end);
  }
}

Feature 2: Stylus Button Customization

Goal: Karl should decide what the stylus button means. The default should be useful immediately, but the app should not force one workflow.

Default mapping

Hold button temporarily switches to eraser. Releasing the button restores the previous tool.

Power mapping

Button + drag can become lasso, pan, straight-line mode, arrow mode, or selection move.

Fast actions

Button tap can undo, redo, toggle previous tool, open a radial menu, or copy/export selection.

Input Model

CanvasView already owns raw pointer events. Extend this layer with a StylusGestureMapper that reads stylus kind plus button bitmask, then resolves a gesture before routing to the controller.

Feature 3: PNG/JPG Export

Goal: export should be fast when Karl needs to send a quick image, and high-quality when he wants to archive or share polished notes.

Export pipeline

Choose scope Entire content, viewport, or current lasso selection.
Compute region Union bounds plus padding, or visible world rect.
Render offscreen Record a world-to-image transform into ui.PictureRecorder.
Encode PNG lossless or JPG with selected quality.
Save/share Write to export folder, copy path, or later use Android share sheet.

Export scopes

  • Entire canvas content: union of all element bounds, with padding.
  • Current viewport: visible world rect from viewport and surface size.
  • Lasso selection: selectedElements and selectionBounds.
  • Future: named bookmark/region export.

Quality controls

  • Presets: Low, Medium, High, Original/Archive.
  • Custom scale: 1x, 2x, 3x, or target width.
  • PNG: quality mostly means scale and transparency, because PNG is lossless.
  • JPG: quality maps to encoder quality, with transparent exports forced onto paper/background color.

Important Encoding Decision

Flutter's built-in ui.Image.toByteData supports PNG easily, but JPG quality requires either a Dart image encoder package or a platform-specific Android encoder. The cleanest implementation is to add the image package and encode JPG from raw RGBA bytes.

When implementation starts, this dependency addition should be explicit because it changes the project dependency graph.

Implementation Details

Concern Plan
Renderer reuse Extract shared element painting into a renderer that both ElementsPainter and CanvasExportService can call. Avoid duplicating shape/image/text/link paint logic.
High-quality imported images/PDFs MVP can use loaded runtime rasters. Full version should decode source images and rasterize PDFs for the requested export scale before rendering.
Huge exports Add a max pixel count guard, show a clear message, and suggest a lower scale. This prevents memory crashes.
Selection export If no selection exists, disable the selection option. Use selection bounds shifted by live drag delta only after drag commit.
Transparency Only PNG can be transparent. JPG should force paper background and disable the transparent toggle.

Feature 4: Infinite Zoom

Goal: zoom should feel endless enough for thinking: big maps, tiny details, no jumps, and no data precision problems.

Already working

  • Wheel zoom anchors under the cursor.
  • Pinch zoom anchors around the gesture midpoint.
  • Strokes and elements live in world coordinates.
  • Rendering culls through SpatialIndex.
  • Tile cache exists for committed elements.

Needed for deep zoom

  • Wider scale range with level-of-detail rendering.
  • Fit content, fit selection, zoom to 100%, and zoom to last working area.
  • Origin rebasing using existing worldOriginX/Y columns.
  • Screen-stable UI chrome: lasso borders, handles, hover rings, labels.
  • Export and minimap must use the same world bounds math.

Scale Philosophy

Ink should default to paper-scale. If Karl zooms in and writes, he can create smaller thoughts. UI chrome should be screen-scale. Selection outlines, handles, lasso borders, hover rings, labels, and toolbar controls should remain readable at any zoom.

Implementation Plan

Phase Work Why
Quick wins Add fitContent, fitSelection, zoomTo100, and better zoom labels. Improves navigation immediately and supports export framing.
LOD rendering At low zoom, simplify stroke paths and skip tiny details. At high zoom, keep full outlines. Large canvases stay fast when zoomed out.
Scale expansion Widen minScale/maxScale after tests prove selection, eraser, lasso, and export remain stable. A true-feeling infinite canvas needs more range, but it must not break editing.
Origin rebasing Use worldOriginX/Y when the active area drifts far from origin. Rebase by translating all active geometry and adjusting viewport. Prevents floating-point precision issues on massive canvases.
Minimap Build a lightweight overview from element bounds and current viewport. Deep zoom needs orientation, not just scale. 
ViewportState frameWorldRegion({
  required Rect region,
  required Size viewportSize,
  double fillFraction = 0.82,
}) {
  final viewEdge = viewportSize.shortestSide * fillFraction;
  final scale = CanvasTransform.clampScale(viewEdge / region.longestSide);
  final screenCenter = Offset(viewportSize.width / 2, viewportSize.height / 2);
  final translation = screenCenter - region.center * scale;
  return ViewportState(translation: translation, scale: scale);
}

Feature 5: Smarter Pen

Goal: make ink feel more like Karl's hand intended, without correcting or interpreting his thinking.

Explicit non-goal: no shape recognition. No "hold and convert to perfect circle/box/arrow" behavior. The smarter pen should improve feel, not decide meaning.

Adaptive smoothing

Slow strokes preserve detail. Fast strokes get more smoothing. This reduces jitter without making handwriting feel delayed.

Pressure curves

Light, normal, firm, and custom curves let the S Pen feel right for Karl's hand.

Stabilizer

Off, low, medium, high. Higher values trade latency for smoother deliberate lines.

Natural taper

Better starts and ends reduce blobs and hard cutoffs.

Hover preview

Show width/color/tool under the stylus before touching the screen.

Manual straight/snap modes

Triggered by stylus button or explicit tool state, never automatic.

Engine Approach

The current stroke model stores x, y, and normalized pressure. For the first smarter-pen pass, keep that storage format and improve the capture pipeline before points are committed. This avoids a risky ink BLOB migration. 

enum PressureCurveKind {

  firm,

Improvement Where it lands Data impact
Pressure curve Map raw normalized pressure in CanvasView._pressure or a new PenInputProcessor. No stroke migration. Stored pressure is already the interpreted pressure.
Stabilizer Filter incoming points before appendToStroke. No migration. Stored points are the stabilized centerline.
Smoothing/streamline Pass profile values into buildStrokeOutline for live and committed strokes. May need profile persisted per stroke if old strokes must keep exact rendering. MVP can use tool defaults only if acceptable.
Velocity-aware width Prefer deterministic point-distance based calculation unless timestamp persistence is added. Avoid timestamp BLOB migration in first pass.
Pen presets Toolbar popover and settings page. Persist in per-canvas tool settings and global defaults.
If per-stroke profile fidelity becomes important, add a strokeProfileJson or structured columns to InkStrokes. Do this only after deciding that old ink must render exactly with the settings active when it was created.

Implementation Roadmap

This sequence keeps the app usable after each milestone and avoids mixing the riskiest changes together.

Phase 0

Baseline and safety

Run current tests, record current arrow behavior, confirm generated Drift migration flow, and add a small stylus-button diagnostic if needed.

Exit: baseline known, no mystery failures.
Phase 1

Arrow system and quick zoom commands

Add arrow styles, shared arrow renderer, schema migration, toolbar popover, fit content, fit selection, and 100% zoom.

Exit: new arrows look good and old arrows still load.
Phase 2

Export MVP

Implement content/viewport/selection export to PNG first, with scale presets, padding, background controls, and max pixel guard.

Exit: Karl can export a selected lasso region and entire canvas safely.
Phase 3

JPG export and presets

Add JPG encoder path, quality slider, transparent-background rules, export presets, and optional share/copy affordances.

Exit: PNG/JPG both work from low to high quality.
Phase 4

Stylus button customization

Add settings model, UI, temporary-tool stack, button hold/tap/drag mapping, and hardware verification on S Pen.

Exit: stylus button can be mapped to eraser, lasso, pan, straight line, undo, or toggle tool.
Phase 5

Smarter pen

Add pen profile, pressure curves, adaptive smoothing, stabilizer, taper tuning, hover preview, and manual straight/snap mode.

Exit: pen feels better without automatic shape conversion.
Phase 6

Deep infinite zoom

Add wider scale range, level-of-detail rendering, origin rebasing, minimap, and export-aware high-resolution raster handling.

Exit: huge canvases remain fast, accurate, and navigable.

Validation Plan

Validation should combine Dart unit tests, Flutter widget tests, render checks, and one real-tablet manual pass.

Automated tests

  • Arrow geometry: head size, tangent direction, bounds inflation, curved/elbow paths.
  • Repository round-trip: new shape style fields and default legacy rows.
  • Controller: shape commit, undo/redo, selection bounds with styled arrows.
  • Export: scope bounds, transparent/JPG rules, max pixel guard, empty canvas behavior.
  • Input: stylus mapping state machine, temporary tool restoration, tap vs drag threshold.
  • Transform: fit content, fit selection, zoom anchoring, widened scale boundaries.
  • Pen: pressure curve math, stabilizer sample output, profile persistence.

  • Draw every arrow style at widths 1, 4, 12, 20 and at multiple zoom levels.
  • Use S Pen button hold, tap, and drag mappings in a real note-taking flow.
  • Export entire canvas, viewport, and lasso selection as PNG and JPG.
  • Try transparent PNG over another app/background.
  • Zoom far out, fit content, fit selection, zoom back into tiny handwriting.

Risks And Guardrails

Risk Guardrail
Schema migration accidentally changes existing notes. Add only nullable/defaulted columns. Round-trip old rows in tests. Preserve legacy rendering.
Export crashes on huge canvases. Estimate pixel count before rendering. Clamp presets and show a useful message.
Stylus button events differ by hardware. Run a diagnostic on the target tablet before building assumptions into UX.
Smarter pen feels laggy. Make stabilizer optional and default low. Keep raw-feeling pen available.
Deep zoom introduces precision drift. Use origin rebasing after tests and preserve all geometry through undoable commands or explicit transactions.
Too many controls clutter the canvas. Use compact popovers, defaults, and presets. Keep the first screen focused on writing.

Definition Of Done

This initiative is done when Karl can draw visually clean arrows in multiple styles, map the S Pen button to his preferred workflow, export canvas or lasso-selected notes as low-to-high-quality PNG/JPG, zoom smoothly from overview to tiny details, and write with a pen that feels more stable and natural without ever auto-converting his strokes into recognized shapes.
