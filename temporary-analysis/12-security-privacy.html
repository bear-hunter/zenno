Analyzer 12’s continuous, evidence-based review of Zenno’s local privacy, secrets, permissions, web exposure, dependency attack surface, unsafe input handling, and security boundaries.

Executive summary

Zenno is meaningfully local-first: the shipped Android manifest declares no network permission, application code contains no HTTP client use, user text is painted by Flutter instead of inserted into a browser DOM, and destructive media cleanup is confined to resolved app-owned roots. No credential signature was found in the current repository material reviewed.

The strongest privacy issue is architectural rather than an obvious remote exploit: sensitive note, reflection, distraction, goal, focus, and attachment data is written to ordinary SQLite/IndexedDB and Android backup behavior is not explicitly controlled. The strongest hostile-input issue is unrestricted image/PDF import into full decoders and native PDFium. The web target has no demonstrated app-input injection path, but the existing generated bundle fetches executable CanvasKit from Google’s CDN and may fetch fonts from Google while the note database remains available to scripts on the Zenno origin. That makes remote runtime supply and origin integrity decisive security boundaries.

Findings

SEC-01 — Android backup policy is implicit while the app holds private learning data

HIGHConfidence: high

Root cause. The main application manifest does not set android:allowBackup, android:fullBackupContent, or android:dataExtractionRules. Android’s default backup behavior can therefore include eligible app-private database/document files. Zenno’s data model explicitly contains note text, reflection answers, distraction notes, goal/status notes, focus goals, images and PDFs.

  • android/app/src/main/AndroidManifest.xml:2-6 defines the application without a backup policy.
  • lib/core/database/tables/canvas_tables.dart:275-290 stores multiline canvas note bodies.
  • lib/core/database/tables/reflection_tables.dart:23-47 stores template snapshots and reflection answers.
  • lib/core/database/tables/focus_tables.dart:39-80,105-116 stores goals, focus notes, and distraction text.
  • lib/canvas/io/canvas_import.dart:146-164 copies chosen media into the application documents directory.
  • The locked drift_flutter 0.2.8 implementation also defaults native driftDatabase to getApplicationDocumentsDirectory(). This contradicts the “app-support directory” comment at lib/core/database/connection.dart:9 and reinforces the need to verify the actual backup file set rather than rely on that comment.
Privacy
Private notes/media may leave the tablet through platform backup or device transfer without a Zenno-specific, visible consent boundary.
Flow/data integrity
A restore may surprise the user with older state or missing large media; disabling backup without replacement would instead increase loss risk.

Analysis-only recommendation. Make an explicit product decision. For strict local-only privacy, opt out of cloud/device-transfer backup with modern and legacy rules. For resilience, prefer an encrypted, user-initiated Zenno backup/export and tightly scoped platform backup rules. Do not simply disable backup without first addressing the project’s “data integrity is absolute” requirement.

SEC-02 — Notes and study history are not encrypted at the application layer

HIGHConfidence: high

Root cause. Native persistence opens ordinary Drift SQLite, and web persistence opens ordinary SQLite WASM over IndexedDB. No encryption key lifecycle, encrypted database engine, or encrypted-media layer is present in dependencies or storage code. OS app sandboxing and browser origin isolation are the current confidentiality controls.

  • lib/core/database/connection_native.dart:1-4 opens driftDatabase(name: 'zenno').
  • lib/core/database/connection_web.dart:9-18 loads sqlite3.wasm, opens an IndexedDB filesystem named zenno, and stores /database.
  • pubspec.yaml:30-52 includes Drift/SQLite but no SQLCipher or secure-key-storage dependency.
  • lib/core/database/tables/canvas_tables.dart:190-230 stores absolute imported PDF/image paths alongside the plaintext database content.
Privacy
A rooted/unlocked device, extracted backup, malicious same-origin web script, compromised browser profile, or forensic access can read meaningful learning history directly.
Flow/data integrity
Encryption retrofits carry migration/key-loss risk; a rushed change could make all notes unreadable.

Analysis-only recommendation. First document the threat model: stolen locked device, shared OS account, cloud backup operator, malicious website on the same web origin, or local malware. If protection beyond the OS sandbox is required, design authenticated encryption for database plus media, with tested crash-safe migration, recovery/export, and key-loss handling. Treat this as a deliberate data architecture project, not a package swap.

SEC-03 — Image and PDF imports have no pre-decode size or complexity budget

MEDIUM-HIGHConfidence: high

Root cause. Picked files are copied before validation. Images are then read wholly into memory and decoded at intrinsic resolution. The controller’s 96 MiB raster budget applies only after decoding, so it cannot prevent peak allocation. Decoder objects are disposed only on the success path. PDFs are opened by native PDFium, every page is enumerated, the controller creates one element per page, and every distinct opened document remains in an unbounded map until the canvas controller is disposed. File extension/MIME selection is not a content-size, page-count, decompression-ratio, resource-lifetime, or parser-safety boundary.

  • lib/canvas/io/canvas_import.dart:87-107 copies the image, calls readAsBytes(), and decodes with no byte/pixel cap.
  • lib/canvas/io/canvas_import.dart:96-101 disposes the image codec only after getNextFrame() succeeds; an exception after codec creation bypasses disposal. The reload path at lib/canvas/canvas_controller.dart:4299-4317 similarly lacks finally cleanup for partially created buffer/descriptor/codec objects.
  • lib/canvas/io/canvas_import.dart:115-131 accepts a .pdf pick, copies it, then probes the entire document.
  • lib/canvas/pdf/pdf_raster_service.dart:108-132 opens the file through pdfrx/PDFium and materializes page metadata for every page.
  • lib/canvas/pdf/pdf_raster_service.dart:84-113,233-247 caches one open PdfDocument future per path with no entry cap/eviction and closes them only at service disposal.
  • lib/canvas/canvas_controller.dart:3977-4013 creates one canvas element per PDF page without a page-count cap.
  • lib/canvas/pdf/pdf_raster_service.dart:174-184 caps final page raster dimensions to 4096 pixels, and lib/canvas/canvas_controller.dart:448-461,4438-4488 enforces a 96 MiB live raster cache. These useful downstream controls do not bound image decode peak, probing, page count, or open document handles.
Security/availability
A malicious or merely enormous image/PDF can exhaust memory, spend excessive CPU/native-parser time, or crash the app.
Note-taking flow
Import hangs or process death interrupts thought flow; persisted notes should survive, but unsaved in-memory work may be at risk depending on save timing.

Analysis-only recommendation. Define user-friendly byte, decoded-pixel, page-count, open-document, and placement budgets before decoding. Probe metadata defensively where the library supports it, reject or ask to import a page range, use try/finally for every native/engine resource, evict/close idle PDF handles, rasterize thumbnails under strict caps, and keep native PDF/image dependencies current through an explicit security-review cadence.

SEC-04 — Debug/profile variants share the release app identity and signing key while enabling debug/network access

HIGH on a data-bearing dev tabletConfidence: high

Root cause. The release build explicitly uses the debug signing configuration. No build type adds an application-ID suffix, so debug, profile, and release are all com.bearhunter.zenno. Existing merged manifests confirm that debug/profile are debuggable and request Internet while release does not. Because the variants use one app identity and compatible debug signing, installing a development variant can place the more permissive/debuggable build over the same private app-data sandbox rather than isolating test data from real notes.

  • android/app/build.gradle.kts:22-38 defines one applicationId, no debug/profile suffix, and assigns release the debug signing config.
  • build/app/intermediates/merged_manifests/debug/processDebugManifest/AndroidManifest.xml:3-4,15,40-43 observes package com.bearhunter.zenno, version code 1, Internet permission, and android:debuggable="true".
  • The profile merged manifest has the same package/version/Internet/debuggable state; the release merged manifest has the same package/version but no Internet or debug flag. The configured Flutter Gradle plugin creates profile with initWith(debug), including its signing baseline.
  • android/.gitignore:10-14 correctly excludes common keystore formats and key.properties, but exclusion is not variant isolation or release-key governance.
Security/privacy
An accidental or compromised debug/profile build can inherit access to the real Zenno database while enabling ADB debugging and network capability. Anyone controlling the development host/debug signing key has a much stronger route into the data-bearing app identity.
Data integrity/flow
Moving to a proper release key later cannot be treated as an ordinary in-place update. A signature or package-ID transition can strand existing notes unless a tested export/import migration precedes it.

Analysis-only recommendation. Separate development variants with an applicationIdSuffix and distinct visible label/data, then establish a protected release key outside the repository. Before changing the identity/signature of the currently installed data-bearing app, inventory which variant/key signed it and design a verified, reversible note migration. Do not uninstall or replace the existing app until its notes are independently recoverable.

SEC-05 — Existing web output loads executable CanvasKit from Google while notes live in script-readable IndexedDB

HIGH if web is usedConfidence: high

Root cause. The source entry point uses Flutter’s default bootstrap and does not select the generated local CanvasKit directory. The existing generated build config selects the CanvasKit renderer and supplies an engine revision but not useLocalCanvasKit or a local canvasKitBaseUrl; the loader therefore constructs an HTTPS URL under www.gstatic.com and dynamically imports CanvasKit. The generated engine also contains a fonts.gstatic.com fallback for missing glyphs. Cross-origin delivery does not sandbox imported code: it executes with the page’s script authority, while Zenno’s entire database is in that page origin’s IndexedDB. The database and Web Lock names are origin-wide, not scoped by URL path, so unrelated code hosted at another path on the same origin shares the confidentiality boundary. This is a runtime supply/privacy boundary, not evidence that Google is malicious or currently compromised.

  • lib/core/database/connection_web.dart:9-18 stores Zenno under a fixed origin-wide IndexedDB filesystem name zenno and path /database.
  • web/index.html:1-46 contains no CSP declaration or custom loader configuration and loads the generated relative flutter_bootstrap.js.
  • build/web/flutter_bootstrap.js:1,36 chooses https://www.gstatic.com/flutter-canvaskit/<engineRevision> unless local CanvasKit is requested; the observed build config selects renderer:"canvaskit" without that request.
  • build/web/main.dart.js:38494-38495 contains the same Google CanvasKit base fallback; :39908 contains a Google Fonts base fallback.
  • Local CanvasKit and PDFium files are present under build/web/canvaskit/ and build/web/assets/packages/pdfrx/assets/; PDFium’s generated URLs are same-origin, but the current CanvasKit loader still selects Google’s URL.
  • .claude/CLAUDE.md:14 describes web as a development-preview target, and no hosting configuration was found, which limits current production reachability.
  • lib/core/database/web_database_lock.dart:11-41 correctly uses an exclusive cross-tab lock to protect write integrity, not confidentiality.
Privacy/supply chain
Opening web Zenno contacts Google and gives remotely delivered renderer code the same effective access to the page and its note database as bundled app code. The request also discloses ordinary connection metadata.
Availability/data integrity
Offline or blocked-CDN startup can fail despite local CanvasKit artifacts. A compromised runtime dependency or same-origin script could read, alter, or erase IndexedDB; clearing site data remains a separate loss risk.

Analysis-only recommendation. If web stays a dev preview, label it clearly and do not load real private notes there. If it is used with real data, custom-bootstrap the already-bundled CanvasKit from a same-origin path, bundle required fonts, dedicate the origin, and set/test strict response headers (CSP, framing restrictions, MIME sniffing protection, and referrer policy). Verify offline startup from a clean browser profile and add a user-controlled export/restore story. CSP directives must be tested against Flutter’s actual renderer/worker/WASM requirements.

SEC-06 — The design-prototype server binds all interfaces while presenting itself as localhost-only

MEDIUM (developer artifact)Confidence: high

Root cause. The untracked prototype helper passes an empty host string to TCPServer, which binds every available interface, while its instructions print only localhost. Request logging is disabled, reducing visibility into unexpected LAN access.

  • UIUXdesign/serve.py:31-41 silences logs and constructs TCPServer(("", port), handler).
  • UIUXdesign/serve.py:44-55 starts five servers on ports 8001–8005.
  • UIUXdesign/README.md:10-26 describes the endpoints only as localhost.
Exposure
Devices on the same network may retrieve the design prototypes while the helper is running.
Production impact
No Zenno note database is served by this helper; impact is limited to repository design material unless sensitive content is later embedded.

Analysis-only recommendation. Bind explicitly to 127.0.0.1 (and optionally ::1), state the boundary accurately, and retain at least concise access/error visibility. This file is currently untracked and not part of the shipped Flutter application.

SEC-07 — Local prototypes/plans contact third parties; one plan executes unpinned CDN scripts

LOW-MEDIUM (developer privacy)Confidence: high

Root cause. All five untracked UI prototypes load Google Fonts, which discloses a network request when opened. An untracked HTML plan loads Highlight.js and Mermaid from public CDNs without Subresource Integrity. Remote plan scripts execute in the document and could read/exfiltrate its DOM if the CDN response or dependency is compromised.

  • UIUXdesign/01-aurora/index.html:7-9, 02-atelier/index.html:7-9, 03-zen/index.html:7-9, 04-bold/index.html:7-9, and 05-command/index.html:7-9 load Google font resources.
  • plans/2026-06-01-infinite-zoom-pen-plan.html:7,863-864 loads CSS/JavaScript from cdnjs and jsDelivr without integrity attributes.
  • web/index.html:1-46 does not contain these prototype/plan resource tags. The separate generated-web CanvasKit/font boundary is documented in SEC-05.

Analysis-only recommendation. For local/private artifacts, use system fonts and checked-in/self-contained rendering, or pin external resources with integrity and a restrictive CSP. Avoid placing real note content, secrets, or customer data into HTML that executes remote scripts.

SEC-08 — Dormant Zenno document decoding serializes and trusts absolute media paths

MEDIUM if exposed; LOW nowConfidence: high

Root cause. The document codec exports absolute sourceFilePath strings for images/PDFs and reconstructs elements from those strings without copying, rebasing, allowlisting, or embedding media. A shared document can leak device path structure; an imported hostile document could point later file decoders/exporters at arbitrary readable paths. Current repository search finds decoder use only in tests, so there is no production import route today.

  • lib/canvas/io/zenno_document.dart:191-205 writes absolute media paths into JSON.
  • lib/canvas/io/zenno_document.dart:274-291 trusts decoded sourceFilePath values.
  • lib/canvas/canvas_controller.dart:4269-4317,4327-4337 opens element paths for image/PDF rendering.
  • lib/canvas/io/canvas_export.dart:330-352 checks/opens source paths when preparing exports.
  • Repository-wide references to decodeDocument occur only in lib/canvas/io/zenno_document.dart and test/zenno_document_test.dart:63-81.

Analysis-only recommendation. Before wiring document import/export into UI, define a self-contained package format, embed media under generated IDs, reject path traversal/symlinks, enforce file/element/point budgets, and import transactionally into an app-owned staging directory. Never honor serialized absolute paths.

SEC-09 — Gradle’s executable bootstrap is ignored/untracked and its downloaded distribution is not checksum-pinned

MEDIUM (build supply chain)Confidence: high

Root cause. The repository tracks only gradle-wrapper.properties. android/.gitignore explicitly excludes gradle-wrapper.jar, gradlew, and gradlew.bat; local copies exist, including an executable script, but are not reviewable or reproducible from Git. The properties file then downloads a Gradle -all.zip over HTTPS without distributionSha256Sum. The bootstrap JAR/script executes before normal Gradle dependency resolution, so “HTTPS” alone is weaker than repository-controlled code plus an official distribution hash.

  • android/.gitignore:1-5 ignores the wrapper JAR and launchers.
  • git ls-files android/gradle/wrapper android/gradlew android/gradlew.bat returns only android/gradle/wrapper/gradle-wrapper.properties, while local filesystem inspection finds ignored gradle-wrapper.jar and executable android/gradlew.
  • android/gradle/wrapper/gradle-wrapper.properties:1-5 specifies Gradle 8.14 without a checksum.
  • android/settings.gradle.kts:13-23 uses Google, Maven Central and Gradle Plugin Portal with fixed Android/Kotlin plugin versions.
  • pubspec.lock contains 152 hosted and 4 SDK packages; hosted entries include package hashes and no Git/path dependency was found.

Analysis-only recommendation. Choose and document one trust model: either track/review the standard wrapper JAR and launchers, or reproducibly regenerate and verify them from a pinned Flutter/Gradle toolchain before use. In both cases pin the official Gradle distribution SHA-256 and consider Gradle dependency-verification metadata for plugins/libraries. Maintain a review/update process for Flutter, PDFium, SQLite, file picker and other native plugins. No specific CVE is claimed because this analysis intentionally performed no online advisory lookup or dependency execution.

SEC-10 — Canvas exports are persistent private copies with no retention or deletion path

MEDIUMConfidence: high

Root cause. Every export is written under the application documents directory in canvas_exports. The library’s deletion and orphan-cleanup code only knows database-referenced thumbnails/imported images/PDFs and only sweeps canvas_media and thumbnails. No code lists, expires, deletes, or associates exports with their source canvas.

  • lib/canvas/io/canvas_export.dart:130-163 writes timestamped SVG/PNG/JPG/PDF files under documents/canvas_exports.
  • lib/features/library/data/library_file_cleanup_io.dart:54-59 limits owned cleanup roots to canvas_media and thumbnails.
  • lib/features/library/data/library_repository.dart:187-251 deletes only a canvas thumbnail and image/PDF paths referenced by its elements.
  • Repository-wide search finds canvas_exports only at its creation point; the toolbar merely reports the absolute output path at lib/canvas/widgets/canvas_toolbar.dart:1999-2013.
Privacy/deletion semantics
Deleting or rewriting the source note does not remove its old rendered snapshots. Those copies can survive unnoticed and may also enter Android backup under the same implicit policy as other documents.
Flow
The user has no in-app way to find or clean sensitive exports, and an absolute sandbox path in a transient snackbar is not an actionable destination on Android.

Analysis-only recommendation. Make exports user-directed: save/share through a platform destination the user understands, or provide an in-app export manager with age/source metadata and explicit deletion. Decide whether internal exports belong in platform backups. Never auto-delete user exports until ownership and expectations are explicit.

SEC-11 — An unlocked/shared tablet exposes Zenno immediately and Android may retain visible task snapshots

MEDIUM (threat-model dependent)Confidence: high

Root cause. Startup routes directly to the library. There is no app-level authentication/biometric gate, lifecycle privacy cover, secure-window flag, or recents-preview policy. Focus mode defaults to keeping the display awake and visibly renders the study goal. This is not a bypass of Android’s device lock; it means Zenno adds no second boundary for a borrowed/unlocked tablet, unattended focus session, screen sharing, screenshots, or app-switcher previews.

  • lib/main.dart:7-15 initializes and runs the app directly.
  • lib/config/router/app_router.dart:25-38 sets the library as the initial route without a guard.
  • android/app/src/main/kotlin/com/bearhunter/zenno/MainActivity.kt:1-5 is an uncustomized FlutterActivity.
  • Repository search found no FLAG_SECURE, recents-screenshot control, lifecycle privacy overlay, biometric/local-auth dependency, or passcode gate.
  • lib/core/database/tables/settings_tables.dart:42-43 defaults keepScreenOnInFocus to true; lib/features/focus/application/focus_wakelock_service.dart:6-18 applies the platform wakelock and lib/features/focus/presentation/pages/focus_active_page.dart:273-300 displays the goal while active.
Privacy
Someone with temporary access to the unlocked tablet can browse notes, reflections, goals, distractions, and imported material. Note content may be captured in screenshots, recordings, or task thumbnails; an unattended default focus session can delay automatic display lock while showing its goal.
Flow tradeoff
A mandatory unlock prompt or screenshot ban could disrupt learning and legitimate capture/export, so the least intrusive control depends on Karl’s actual threat model.

Analysis-only recommendation. Decide whether the device lock is sufficient. If not, prefer an optional “private mode”: obscure content in recents/background, optionally require device biometrics after a configurable timeout, and let the user deliberately permit screenshots when needed. Test focus-timer continuity and crash recovery so privacy controls do not cost note integrity.

SEC-12 — Raw exception strings from private file/database operations are emitted to debug logs

LOWConfidence: medium-high

Root cause. Many catch paths interpolate the full exception into debugPrint. File-system exceptions commonly include absolute selected/app paths, and database/plugin exceptions can contain internal operational detail. Flutter’s debugPrint is a logging API, not a redaction boundary.

  • lib/canvas/canvas_controller.dart:3935-3940,4016-4021 prints raw image/PDF import errors after handling them for the UI.
  • lib/features/library/presentation/widgets/canvas_card.dart:39-45,109,160,205 prints raw library persistence/navigation failures.
  • lib/features/focus/application/active_session_controller.dart:112,179-184,369,440-445,490 prints raw focus-runtime persistence/wakelock failures.
  • Similar raw logging occurs in reflection, settings/tool-wheel, attachment, and focus-page paths.

Impact. ADB-authorized, privileged, diagnostic, or collected logs may reveal local path structure and failure details. No direct evidence showed note bodies or credentials being logged, so severity remains Low.

Analysis-only recommendation. Keep user-facing generic errors, but gate detailed logging to non-release builds or log stable error categories without paths/record content. Review crash-reporting privacy before adding any telemetry in the future.

SEC-14 — Unsynchronized orphan cleanup can delete a newly imported file from a stale reference snapshot

MEDIUMConfidence: high on race; timing-dependent reachability

Root cause. Constructing LibraryRepository launches orphan cleanup with unawaited and immediately exposes the repository/UI. Cleanup snapshots all database paths and later sweeps the media directories against that frozen set. Image/PDF import independently copies a new file into canvas_media before decoding/probing and before the controller’s asynchronous element upsert makes the path durable. There is no lock, startup barrier, staging directory, or final “still unreferenced?” query at deletion time.

  • lib/features/library/application/library_providers.dart:15-24 starts cleanupOrphanedFiles() without awaiting it.
  • lib/features/library/data/library_repository.dart:28-45 builds one reference set, then passes it to the filesystem sweep.
  • lib/features/library/data/library_file_cleanup_io.dart:29-47 deletes every file absent from that snapshot, without rechecking the database.
  • lib/canvas/io/canvas_import.dart:96-101,125-126,151-164 creates the swept file before image decode/PDF probe completes.
  • lib/canvas/canvas_controller.dart:3910-3933,3994-4015 only schedules persistence after import work; element persistence itself is asynchronous (lib/canvas/canvas_controller.dart:945-987).
  • Existing library tests cover delete-time shared-file preservation (test/library_repository_test.dart:128-176) but repository search found no orphan-cleanup/import concurrency test.
Data integrity
A valid just-picked media copy can disappear. Import may fail immediately, or the canvas may retain an element whose raster works only until eviction/restart while its durable source path is already gone.
Flow/recoverability
The race is easiest near repository startup/recreation and may be intermittent. The original picker source often survives, but content-provider/cache sources are not guaranteed to remain available—the exact reason Zenno copies them.

Analysis-only recommendation. Serialize cleanup with every media import/thumbnail writer, or complete cleanup as an awaited startup barrier before content actions become available. A safer design stages new files outside swept roots, performs the database/file commit under one application-level mutex, and rechecks authoritative references immediately before any deletion. Add a deterministic concurrency test that pauses cleanup between snapshot and sweep while importing a file.

SEC-15 — Text inputs and render/persistence paths have no content-size budget

LOW-MEDIUM (local availability)Confidence: high

Root cause. UI fields use maxLines for layout but no maxLength or byte budget. Canvas notes are then laid out as an unlimited-line TextPainter and written whole to SQLite. Reflection answers, card notes/titles, goals, distractions, folders and other text fields follow the same unconstrained pattern. Input is local today, so this is accidental/self-induced denial of service rather than remote injection.

  • lib/canvas/canvas_editor_page.dart:349-395 accepts an arbitrary-length note.
  • lib/canvas/render/elements_painter.dart:840-880 lays out the full note with maxLines: null on paint.
  • lib/canvas/persistence/canvas_repository.dart:455-464 writes the full string.
  • lib/features/goal_cycle/presentation/widgets/reflection_form.dart:122-150 and lib/shared/kanban/kanban_column_view.dart:865-899 likewise constrain visible lines but not content length.
  • Repository search found no UI maxLength: declaration; matches named maxLength only as unrelated geometry parameters.

Impact. Pasting a very large study text can cause editing/render stalls, memory pressure, large database writes/backups/SVG rendering, and an interruption to note-taking flow. The JSON document codec is dormant (SEC-08) and is not treated as a current export route.

Analysis-only recommendation. Establish generous per-field byte/character budgets based on intended use and surface them before save. For genuinely long-form notes, use bounded/virtualized rendering rather than silent truncation. Existing oversized records must remain readable and exportable during any migration.

Verified protective controls

POSITIVE Release Android manifest has no network or broad storage permission

android/app/src/main/AndroidManifest.xml:1-41 contains neither INTERNET nor external-storage permissions. Internet appears only in debug/profile overlays (android/app/src/debug/AndroidManifest.xml:1-7 and profile equivalent). Application imports show no runtime HTTP client. Transitive http/url_launcher packages are not direct app use.

POSITIVE Media deletion is constrained to resolved owned roots

lib/features/library/data/library_file_cleanup_io.dart:5-27 resolves candidate files and allowed roots before deletion; :29-51 enumerates roots with followLinks: false. This substantially reduces arbitrary-file-deletion risk from corrupted database paths.

POSITIVE SVG text injection is escaped

lib/canvas/io/canvas_export.dart:984-1009,1070-1092,1134-1140 XML-escapes note lines and link labels. Image/PDF content is embedded as PNG data rather than retaining attacker-controlled external URLs.

POSITIVE Browser database uses an exclusive cross-tab lock

lib/core/database/web_database_lock.dart:11-41 fails a second tab before opening the same SQLite file, reducing concurrent-writer corruption risk. This is an integrity boundary, not authentication or encryption.

POSITIVE Basic secret and keystore hygiene is present

.gitignore:26-48 excludes generated/build/Firecrawl material; android/.gitignore:6,10-14 excludes local.properties, keystore files, and signing properties. No tracked sensitive-looking path or common credential signature was found. The ignored android/local.properties exists but its contents were not disclosed.

POSITIVE Raw SQL is static and user values use Drift expressions

Repository-wide search found no interpolated raw SQL in application code. The only customSelect/customStatement calls use fixed schema/aggregate statements (lib/features/library/data/library_repository.dart:115-119; lib/core/database/database.dart:124-156), while IDs/names/paths use Drift equals/isIn expressions. This materially reduces SQL-injection risk.

POSITIVE Existing release component exposure is narrow and permission-gated

The existing merged release manifest exposes the launcher activity, which has only the MAIN/LAUNCHER intent filter. The transitive URL-launcher activity and AndroidX initialization provider are exported="false". AndroidX’s exported profile installer receiver requires android.permission.DUMP, a privileged permission. No deep link, share receiver, custom content provider, or exported note-data service was found.

POSITIVE Element/database mutations are transactionally grouped and foreign keys are enabled

lib/canvas/persistence/canvas_repository.dart:338-376 writes base and kind-detail element rows plus canvas timestamp in one transaction; batch deletion/update paths also use transactions. lib/core/database/database.dart:153-158 enables SQLite foreign keys before normal use, preserving cascade semantics. This protects database-row atomicity, although it cannot make filesystem copies/deletes atomic with the database (the source of SEC-14).

POSITIVE File selection and destination naming avoid broad storage authority and path traversal

lib/canvas/io/canvas_import.dart:87-126 uses the system picker for one typed item rather than requesting broad external-storage permissions. :146-181 copies into an app-owned root under a generated UUID plus only the source basename extension; directory separators cannot enter the destination name. This is a sound path boundary even though size/content/resource validation remains incomplete.

Dependency attack surface

The lockfile contains 20 direct runtime dependencies, 9 direct development dependencies, and 127 transitive dependencies (152 hosted, 4 SDK). No Git or local path source is locked. The meaningful attack surface is not package count alone: Zenno passes user-selected files into native/plugin boundaries including file_picker 11.0.2, pdfrx 2.4.1 / pdfrx_engine 0.4.2 / pdfium_flutter 0.2.1, sqlite3 2.9.4 / sqlite3_flutter_libs 0.5.42, JNI/FFI, and Flutter platform plugins.

Static package-import accounting found no application/test import of four declared direct runtime packages: collection, cupertino_icons, freezed_annotation, and json_annotation. Some may remain transitive/tooling prerequisites, so this is not counted as a vulnerability; verify and remove unnecessary direct declarations to keep intent and review surface minimal.

The repository’s pubspec.lock pins hosted artifacts with SHA-256 values. The manifest’s caret constraints are therefore not by themselves an uncontrolled update path when the lockfile is honored. This pass did not claim any package CVE or freshness issue because no online advisory/version check was authorized or performed.
