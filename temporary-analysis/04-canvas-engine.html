Executive summary

The canvas architecture is generally disciplined: immutable element replacements, a command-backed mutation surface, a synchronized spatial index, layer stamping on current creation paths, and preview-only selection transforms all reduce corruption risk. The strongest current defect is in the touch path: a finger on selected content bypasses the movement threshold used by stylus/mouse selection sessions, so ordinary sub-slop jitter can move notes and create an undo step.

The second high-impact issue is semantic stacking after partial erase. Surviving fragments receive fresh top-of-stack z-indices rather than retaining the erased stroke’s position, so erasing part of a lower stroke can make the remainder jump above later notes or images. Several medium risks cluster around mismatched geometry representations: arrow control geometry is not part of ShapeElement.worldBounds, rotated selection previews transform already-inflated axis-aligned bounds, scale handles use a padded frame as the transform anchor, and fast object-eraser segments can cross rectangular content without either sampled endpoint hitting it.

Adversarial re-reading narrowed one first-pass claim: fractional database z-order is a compatibility hazard, but every current writer and in-repository fixture inspected emits integers. CAN-04-008 is therefore low severity unless older or externally authored rows actually contain fractional values.

No direct note-content deletion path was found outside explicit erase/delete/clear commands. The highest data-integrity concern in this pass is unintended geometry mutation from touch jitter; most remaining findings affect selection reliability, visual order, or recoverability rather than textual payload loss.

Findings

CAN-04-001HighConfidence: high

Sub-slop finger jitter can move selected notes and create history

Impact on flow/data integrity: A normal finger tap on selected content can slightly alter note geometry and consume an undo step. Repeated taps can create imperceptible drift; the effect is persistent because the move is command-backed and written through.

Evidence: lib/canvas/render/canvas_view.dart:400-411 starts beginSelectionDrag() immediately for touch. Pointer moves set _toolPointerMoved only after the 8 px threshold, but still route every move at 529-546; 719-722 forwards even sub-threshold world deltas. Pointer-up commits at 1059-1064. Adding a second finger also calls endSelectionDrag() before beginning the two-touch transform at 906-935, so first-finger jitter can become a separate command even when the intended gesture is pinch/rotate. The controller drops only an exactly zero delta at lib/canvas/canvas_controller.dart:3055-3060. In contrast, the primary stylus/mouse selection session defers activation until slop is crossed at lib/canvas/render/canvas_view.dart:563-580. The named sub-slop regression at test/canvas_view_input_test.dart:504-532 uses a stylus; the touch move test at 392-424 moves 40 px and does not exercise jitter.

Root cause: Touch selection uses the older eager drag lifecycle, while the newer one-pointer selection session implements a deferred activation threshold. Movement classification and movement accumulation are separate, and only the former honors tapSlop.

Analysis-only recommendation: Give touch selection the same deferred session contract: retain the down point, do not call beginSelectionDrag or accumulate deltas until screen movement exceeds tapSlop, then seed the preview with the full down-to-current world delta. Add a touch-specific sub-slop jitter regression and verify that a second finger does not commit a pre-threshold move.

CAN-04-002HighConfidence: high

Partial erase moves surviving stroke fragments to the top of their layer

Impact on flow/data integrity: Erasing a small part of an older stroke can change the visual meaning of the note: every surviving piece may repaint above content that was previously in front (later ink, text, images, or PDFs on the same layer).

Evidence: lib/canvas/canvas_controller.dart:2118-2128 removes the original and constructs each fragment with zIndex: _nextZIndex++. The element list paints by layer then z-index at 762-770, and lib/canvas/render/elements_painter.dart:429-456 preserves that order. Undo restores the original snapshot, but redo reinstalls the promoted fragments through ReplaceElementsCommand (lib/canvas/engine/canvas_commands.dart:136-176).

Root cause: Fresh IDs are correctly used to distinguish fragments, but identity allocation was coupled to top-of-stack z allocation. Fragment identity and paint position are independent concerns.

Analysis-only recommendation: Preserve the original stroke’s stacking slot for all fragments. If a strict total order is required, introduce an explicit stable secondary order or fractional sibling order rather than promoting fragments above unrelated elements. Test an erased lower stroke beneath a later rectangular element and later ink.

CAN-04-003MediumConfidence: high

Shape bounds omit persisted control points used by rendering and hit testing

Impact on flow/data integrity: A curved or elbow arrow with a control point outside the endpoint box plus fixed padding can be partially culled and can become unselectable/uneraseable where it is visibly drawn. This interrupts flow and can leave visible note content difficult to recover.

Evidence: ShapeElement.worldBounds uses only start, end, stroke width, and a fixed 56-unit pad at lib/canvas/model/canvas_element.dart:125-139. Rendering consumes controlPoints at lib/canvas/render/shape_painter.dart:56-63; hit/eraser geometry also consumes them through lib/canvas/canvas_controller.dart:2321-2329. Curved/elbow path construction accepts the first arbitrary control at lib/canvas/tools/arrow_geometry.dart:22-36, and styled heads can extend up to 75 world units before the arrow-length cap (96-105), already exceeding the magic 56 pad for sufficiently long, thick arrows. The spatial index is seeded only from worldBounds at lib/canvas/canvas_controller.dart:807-808, and both lasso and point hits depend on that broad phase at 2622-2632 and 2747-2756. Persistence explicitly round-trips arbitrary control points at lib/canvas/persistence/canvas_repository.dart:467-487 and 302-317. Existing shape tests use default paths or an in-endpoint-span arrow-head point (test/canvas_commands_test.dart:1633-1716); the custom-control test checks tangents, not bounds/indexing (test/arrow_geometry_test.dart:45-83).

Root cause: Bounds remain endpoint-centric after the arrow model grew independent control geometry.

Analysis-only recommendation: Compute conservative bounds from the actual rendered path metrics plus arrowheads and stroke width. Include explicit control points; avoid a magic pad as the primary guarantee. Validate with control points far outside the endpoint rectangle.

CAN-04-004MediumConfidence: high

Non-content layer kinds are still editable once they contain elements

Impact on flow/data integrity: Background, grid, or measurement elements can be selected, transformed, erased, or cleared even though their layer kind says they are not content-editable. Protected structural/reference material may be changed accidentally.

Evidence: CanvasLayer.isEditable requires kind == CanvasLayerKind.content at lib/canvas/model/canvas_layer.dart:29. The controller uses that rule for active creation layers at lib/canvas/canvas_controller.dart:740-759, but element editing checks only visibility and lock state at 655-658. Selection, erasing, delete, and clear all route through _isElementEditable (for example 1987-2012, 2158-2167, and 2625-2633).

Root cause: “Can receive new content” and “can mutate existing content” were implemented as separate predicates, but the latter omitted the layer-kind invariant.

Analysis-only recommendation: Define one explicit policy per layer kind and apply it consistently to create/select/erase/transform/clear. If some non-content kinds should remain editable, encode that intentionally rather than treating every visible unlocked kind as content.

CAN-04-005MediumConfidence: high

Rotated rectangular selections use a doubly conservative preview box that snaps on commit

Impact on flow/data integrity: While rotating or scaling an already-rotated image, PDF, link, or text note, the selection frame can grow or drift away from the content, then snap to a different box on release. Geometry committed to the note remains coherent, but the manipulation feedback is misleading.

Evidence: Rectangular element worldBounds is already the AABB of the rotated placement (for example lib/canvas/model/canvas_element.dart:549-553, 764-768, and 851-855). Live selection bounds then transform the four corners of that AABB at lib/canvas/canvas_controller.dart:610-625. The painter, however, applies the same preview matrix to the actual rotated object at lib/canvas/render/elements_painter.dart:440-445. On commit, placement center/size plus rotation metadata are transformed at lib/canvas/canvas_controller.dart:3274-3391, so the overlay switches back to the true rotated-object AABB.

Root cause: A culling AABB is reused as exact selection geometry. Transforming an AABB of a rotated rectangle is not equivalent to transforming the rectangle itself and then recomputing its AABB.

Analysis-only recommendation: Derive preview bounds from transformed primitive geometry: rotated placement corners for rectangular items, stroke points/outlines for ink, and rendered paths for shapes. Keep index AABBs conservative but separate from manipulation geometry.

CAN-04-006MediumConfidence: high

Scale handles use padded frame corners as transform anchors, causing handle drift

Impact on flow/data integrity: The supposedly fixed opposite corner can move during scale, and the grabbed handle can separate from the pointer. This is most visible at large scale changes and makes precise note layout harder.

Evidence: The overlay inflates projected content bounds by a fixed 6 screen pixels at lib/canvas/render/selection_overlay_geometry.dart:41-67, then exposes those padded corners as handle centers/opposites at 127-144. Scale initialization converts the padded opposite corner to world space and measures handle-to-opposite distance at lib/canvas/render/canvas_view.dart:602-620. The controller scales content about that point at 629-634 and lib/canvas/canvas_controller.dart:3113-3122. Because content scales but the next frame is re-inflated by a constant 6 px (rather than scaled padding), the frame corner is not invariant except at scale 1.

Root cause: Visual chrome padding is mixed into the mathematical transform frame.

Analysis-only recommendation: Keep an unpadded content frame for transform anchors and add screen-space padding only for paint/hit targets. Compute scale from true content corners while retaining 44 px handle hit boxes.

CAN-04-007MediumConfidence: high

Public and persisted viewport states bypass scale/finite validation

Impact on flow/data integrity: A zero, negative, NaN, or infinite saved/link viewport can make the camera matrix non-invertible or propagate non-finite world coordinates, effectively making a canvas inaccessible until reset.

Evidence: CanvasTransform.toWorld assumes scale is strictly positive at lib/canvas/engine/canvas_transform.dart:80-86, and gesture helpers clamp newly computed scales at 89-92. But CanvasController.setViewport assigns arbitrary state unchanged at lib/canvas/canvas_controller.dart:1344-1355; load() also assigns the repository value directly at 903-905. The repository reconstructs ViewportState(scale: row.vpScale) without validation at lib/canvas/persistence/canvas_repository.dart:829-839. ViewportState itself has no invariant enforcement (lib/canvas/model/viewport_state.dart:11-41).

Root cause: Scale validity is enforced only in interactive zoom functions, not at state boundaries.

Analysis-only recommendation: Normalize at every external boundary (repository load, link/document decode, and setViewport): require finite translation/rotation and clamp a finite positive scale, falling back to identity for invalid states. Avoid persisting invalid values.

CAN-04-008LowConfidence: high

Fractional database z-order is rounded into an integer identity/order model

Impact on flow/data integrity: Existing fractional ordering values can collapse to ties after load; a later reinsert, transform, or layer reorder can change which overlapping element paints or hit-tests on top. A subsequent upsert persists the rounded value and makes the loss durable.

Evidence: The schema calls zIndex “fractional z-ordering” and stores REAL at lib/core/database/tables/canvas_tables.dart:156-157. Rows load ordered by the original real value at lib/canvas/persistence/canvas_repository.dart:83-91, but reconstruction rounds it to int at 208-210 and 1044. The engine comparator has no stable secondary key at lib/canvas/canvas_controller.dart:762-770; reinsertion places equals after prior equals at 791-807, while layer moves call a general sort at 1722-1745. Writes serialize only the rounded integer at lib/canvas/persistence/canvas_repository.dart:353-371.

Root cause: Persistence and engine disagree on whether z-order is fractional or integral, with no tie-break contract. The reachable scope is limited: repository writes convert engine integers back to doubles at lib/canvas/persistence/canvas_repository.dart:1047, and the inspected fixtures/current creation paths also use integer values. The defect requires legacy, manually altered, or externally authored fractional rows.

Analysis-only recommendation: Choose one representation and migrate deliberately. If integer order is desired, normalize all rows per canvas/layer while preserving current ordered sequence and add a stable secondary key. If fractional order remains supported, carry it losslessly through the model and comparator.

CAN-04-011MediumConfidence: high

Fast object-eraser segments can pass through rectangular elements without hitting them

Impact on flow/data integrity: A quick eraser sweep can visibly cross an image, PDF page, link, or text note yet leave it untouched when consecutive pointer samples lie on opposite sides. Ink and shapes under the same sweep can erase correctly, making the tool feel nondeterministic across note types.

Evidence: The controller stores raw eraser event positions as a polyline at lib/canvas/canvas_controller.dart:2023-2037. Ink uses segment-aware CanvasGeometry.polylinesWithinDistance at 2191-2209, and shape bodies use the same routine at 2225-2242. Rectangular element kinds instead call _pathReachesRotatedRect at 2210-2219. That helper inverse-rotates only the recorded vertices and delegates to _pathReachesRect (2552-2570), which checks each sample point’s distance to the rectangle at 2533-2549 and never tests the segments between samples. The spatial-index broad phase includes the crossed rectangle because it queries the full path AABB at 2147-2153, so the miss occurs specifically in the narrow phase.

Root cause: Rectangular hit testing models the eraser as a set of circles at event samples, while ink/shape hit testing models the intended swept circle along connecting segments.

Analysis-only recommendation: Test the eraser polyline against the rectangle inflated by the world radius, after inverse rotation when needed: accept a contained endpoint or any segment/edge intersection. Add sparse two-point sweeps crossing each rectangular element kind, plus near-miss and rotated cases.

CAN-04-009LowConfidence: high

Undo/redo history is unbounded for the life of the editor

Impact on flow/data integrity: Long drawing sessions and repeated transforms/partial erases retain complete stroke snapshots indefinitely. Rasters are deliberately stripped, but vector and text payloads can still grow memory until performance degrades or the app is terminated.

Evidence: The controller owns uncapped lists at lib/canvas/canvas_controller.dart:283-287. Every command is appended at 1128-1132, with only redo cleared. Command snapshots retain full elements and point lists (lib/canvas/engine/canvas_commands.dart:85-176, 190-255); no count/byte budget or compaction path is present. History resets only when a new controller is loaded.

Root cause: History correctness was prioritized without a retention policy.

Analysis-only recommendation: Establish a memory-aware history budget, dropping oldest complete commands only after persistence is confirmed. Consider coalescing repeated keyboard nudges and preserve explicit user expectations about maximum undo depth.

CAN-04-010LowConfidence: medium

Ink lasso coverage measures sample count rather than painted length/area

Impact on flow/data integrity: Two visually identical strokes with different sampling density can require different lassos. Pressure-only samples or dense slow regions can outweigh a longer sparse region, making selection feel inconsistent.

Evidence: Ink selection passes every raw StrokePoint to a strict >50% point-count rule at lib/canvas/canvas_controller.dart:2679-2685. CanvasGeometry.polygonCoverage counts points equally at lib/canvas/tools/canvas_geometry.dart:138-153. Capture permits a new point either for distance or a pressure change at lib/canvas/canvas_controller.dart:1279-1299, so point density is not purely geometric. Shapes separately resample path length at 2499-2530.

Root cause: Raw capture samples are reused as geometric coverage samples.

Analysis-only recommendation: Resample ink centerlines by arc length before coverage, or compute inside length directly. Define separate behavior for closed fill regions, where area overlap may match user intent better than boundary point count.

Verified strengths

  • Layer stamping is present on current creation paths. Ink (canvas_controller.dart:1307-1327), shapes (3506-3541), links (3632-3653), text (3710-3730), images (3891-3918), PDFs (3961-4013), and erase fragments (2118-2128) all carry a concrete layer into command history.
  • Command persistence is transaction-shaped. Controller mutations are coalesced by ID (canvas_controller.dart:982-1017) and repository batches are atomic (canvas_repository.dart:530-551).
  • Selection transform commits revalidate live IDs/editability. canvas_controller.dart:3128-3153 prevents a stale preview from resurrecting an element removed or locked during the gesture.
  • Runtime raster identity is kept out of undo snapshots. canvas_commands.dart:5-10 clears image/PDF rasters, avoiding native bitmap retention and double-dispose across history.
  • Rotated rectangular hit testing uses inverse local rotation. canvas_controller.dart:2827-2836 tests the actual placement rectangle rather than its broad AABB.
  • Spatial-index upserts and controller structural mutations are synchronized. Add/remove update both structures at canvas_controller.dart:791-845.
